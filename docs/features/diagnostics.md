### 1.2 操作总分类（来自 `MODULECONFIG_*` 表的 INI 章节 + `MENU` 树）

每个 ECU 在 `MODULECONFIG_MOTORCYCLE_OBDSTARE0xx` 表中以章节定义它能干的事。AE6 PRO（E015）实例如下，**全车型同构**：

| 章节 | 中文 | UDS 语义 | 关键字段 |
|---|---|---|---|
| `[INFO]` | 读 ECU 信息/版本 | `22 <DID>` × N | ItemID/ExpressID 列出 13~33 项 DID（VIN/零件号/供应商/HW/SW/生产日期/批次） |
| `[DS]`→`[VALUEDS]`+`[STATEDS]` | 数据流（数值/状态） | 周期 `22` + 表达式解码 | ItemID/ExpressID 指向数据流表达式（E015 共 **373 条**） |
| `[DTC]` | 读故障码 | `19 02 09` | FaultCmd=`190209`、CodeLen=3、FaultState、FrzCmd=`190400000001`（冻结帧） |
| `[ERASE]` | **清故障码** | `14 FF FF FF` | EraseCmd=`14FFFFFF` |
| `[SPEFUNC]` | **专用功能** | 见下 | MenuID=01,02,03… 每项是一段"输入→安全访问→写"脚本 |
| `[FLASH]` | **刷写** | 见下 | 等级 9 安全访问 + `36/37` 块传输 |
| `[01]/[02]/[03]` | **动作测试 / 例程** | `31` RoutineControl | ChooseModule/EnterCmd/InputCmd/CompleteCmd |

**SPEFUNC 三项（E015 已解密）**：
- `[01] 改 VIN`：`27 01` 取种 → `27 02` 送 key（等级 4）→ `2E F1 90` 写 17 字节 → `11 01` 重启
- `[02] ECU 重启**：`11 01`
- `[03] 写 WiFi 配置**：`27 01/02`（等级 4）→ `2E F0 10` 写 32 字节（热点 SSID/密码，官方通道）

**FLASH 刷写序列（E015 `[01]`）**：`27 09`→`27 0A`（等级 9 安全访问，密钥未破）→ `31 01 02 03` 预编程 → `85 02`/`28 03 03` → `22 F15B/F195/F193` 读指纹 → `2E F15A` 写指纹 → `36/37` 分块传输 → `31 01 FF 01`/`11 01` 复位 → `14 FF FF FF` 清码。

### 1.5 传输层现实（★必读，决定 BLE-485 怎么接）

- **原厂 App 的诊断口是 CAN**（CAN_H/CAN_L，500K，终端电阻一端有即可）。AE8 实测抓包即 CAN 帧（`0x080`/`0x297`…）。
- **RS485 CF/ED 帧**（`43 46 + msgId + len + data + checksum + 45 44`）是**车内部六节点族串口总线**（0x59 MCU / 0x89 TBOX / 0x8B BRS / 0x81 DASH / 0x41 BMS2.0 / 0x51 BMS3.0），走 WiFi/MCP2 路线或内部诊断口，**不是**对外 OBD 诊断主通道。
- 因此"任意 BLE-485 模块"本质是一个**字节管道**：把手机 BLE 转成车端需要的物理口。

### 1.6 VCI 私有封装四层栈(2026-11-06 AE5i Pro 台架实证,★复刻核心)

原厂 App↔VCI 走**经典蓝牙 SPP**(RFCOMM DLCI=2,SDP UUID 0x1101),其上两层私有封装,内嵌车端 CF/ED 帧:

| 层 | App→VCI | VCI→App | 结构(已实证) | 已见命令 |
|---|---|---|---|---|
| L1 链路 | SPP/RFCOMM DLCI=2 | 同 | 经典蓝牙串口 | — |
| L2 配置/鉴权 | `55 AA`+seq(u16BE)+len(u16BE)+payload+尾3B | `AA 55` 镜像(seq 回显) | 帧尾 3B 疑 CRC16+1(待定标) | `FFFA` 状态查询 / `FFEF` 设备信息(返回 VCI SN) / `FEF2` 269B 鉴权 / `FFB2` 许可(含 "CFMOTO"+"hello"+加密 blob) |
| L3 数据 | `56 00`+len(u16**LE**)+seq(1B)+cmd(1B)+data+crc | `AB 00`+len(LE)+seq+… | cmd:`68`=RS485 写(内嵌 CF/ED)、`69`=`690101` 周期轮询、`60`=通道配置(波特率/主从) | 应答 payload=seq+递增计数+`1400`状态+crc |
| L4 车端 | CF/ED(`43 46`+msgId+len+data+校验+`45 44`) | 同 | **透明桥**:VCI 原样转发 | msgId:`0x41`BMS2.0/`0x51`BMS3.0/`0x59`MCU/`0x81`DASH/`0x89`TBOX/`0x83`节点表/`0x88`VIN |

**结论:VCI = 受控 RS485 透明桥**。`BleRs485Backend` 实现要点 = L2 握手(FFFA/FFEF/FEF2/FFB2)+ L3 封装(56/ab + cmd 68/69/60);物理口换成任意 BLE-485 模块(或自实现 SPP)即可脱离官方 VCI。

**台架实测结果**(AE5i Pro,台架 VIN `358122400043936`):
- 版本信息(所有车型):主从切换成功,DASH(0x81) 应答 VIN;msgId 0x83 返回总线节点表
- 故障码:ECU 扫描 3/3(DASH/T-BOX/MCU 在线);**MCU: E085 欠压故障**(真实 DTC)
- 数据流:`690101` ~10ms 轮询,5 节点 CF/ED 实时数据(0x41/0x51/0x59/0x81/0x89);实测 电池温度 27℃/总电流 0.0A
- RS485 静默嗅探 30s = **0 帧** ⇒ 总线无自发广播,纯主从轮询制
- App 会话切包:数据流用 **B1_5DGZEEHO V33.23** 引擎(SET.INI 实证);特殊功能菜单=售后更新/NFC 学卡·删卡/一键学习/电池型号管理/胎压匹配;刷写=离线/在线;报文采集=CAN/RS485/一线通/RS485+CAN(针脚 CAN 6-14 / CAN 3-11)
  - **CAN 车型（AE6/AE7/AE8 主流）** → 用 **BLE-CAN 桥**（市售 BLE↔CAN 网关，GATT 透传 CAN 帧）。用户口中的"485"在此语境下即指通用 BLE 串口/总线适配器。
  - **真 RS485 车型（ManualDB 中 `RS485=0008`、AE5i 等）** → 用 **BLE-485 直连**（GATT 透传 CF/ED 帧）。
- **诊断引擎工作在 UDS 层，与物理口无关**：BLE 模块只提供 `send/recv`；引擎读 `CN_DIAG_full.db` 决定发什么 CAN ID / DID / 服务。**后端抽象**让同一套引擎同时支持两种车型。

## 2. SpeedHunter 复刻架构

照开发包总纲 §5 平移，适配 Xposed 模块 + 任意 BLE 适配器：

```
app/
├─ ui/          车型选择 → ECU 选择 → 功能页(版本/DTC/数据流/专用功能/刷写)
├─ diag/        UDS 客户端：会话(10)/保活(3E)/安全访问(27)/ISO-TP(单+多帧+流控)/DID(22/2E)/DTC(19/14)/例程(31)
├─ transport/   BLE 后端抽象：
│                BleBackend { connect(); send(canId,data); recv(); }
│                ├─ BleCanBackend    —— BLE-CAN 桥（CAN 车型）
│                └─ BleRs485Backend  —— BLE-485 直连（CF/ED 车型）
├─ proto/       协议数据库引擎：assets/CN_DIAG_full.db
│                车型(OpeIdCode)→槽位(E0xx)→MODULECONFIG 解析→INFO/DS/DTC/SPEFUNC/FLASH
└─ keygen/      seed-key：AE7 等级1(已有)；AE6 PRO 等级4(SPEFUNC)/等级9(FLASH，待逆向)
```

- **DB 引擎**：把 `CN_DIAG_full.db` 打进 `assets/`，运行时 `SQLiteAssetHelper` 打开；`DiagEngine` 按"车型→ECU→功能"查表生成操作脚本（复用 1.2 的章节语义）。
- **传输抽象**：`BleBackend` 统一 `connect/send/recv`；CAN 后端封装 ISO-TP 单/多帧；RS485 后端封装 CF/ED 帧。两条产品线共用 `diag` UDS 层。
- **关键复用**：现有 `diag/` 包（Hex/IsoTp/Uds/DtcCodec/Rs485）已是引擎基座；`Uds` 需补 `request()` 超时/流控、`DtcCodec` 接 DB、`Rs485` 接 CF/ED 帧。

## 4. 分阶段实施（参照开发包总纲 §5 顺序）

1. **[已完成] 离线内核**：`diag` 包 + 自检。
2. **打库 + DB 引擎**：`CN_DIAG_full.db` 入 `assets/`；`DiagEngine` 实现"车型→ECU→功能"树；中文 GBK/UTF-8 双编码处理（文本表 UTF-8、表达式表 GBK）。
3. **传输后端**：`BleBackend` 抽象 + `BleCanBackend`（GATT 透传 CAN 帧）+ `BleRs485Backend`（CF/ED）；先 `probe_listen` 收周期帧验物理层。
4. **只读五步链**：`10 03` → `3E 80` 保活 → `22` 读 DID（版本/VIN）→ `19 02 09` 读 DTC → 退出。AE7 加 seed-key 等级1 解锁。

6. **专用功能**：改 VIN / 重启 / 写 WiFi（操作前先 `27` 安全访问；写入需用户明确授权，遵守安全红线）。
